# models

The toolkit behind the trained predictors: machine learning models fitted to real plays. Each trained predictor keeps its own model files next to its code; this package is what they share.

API (`from shared.models import ...`):

- `models_of(file, cuts=None, name="model", limit=None, several=False) -> load(season) -> probability | None`: a cached loader for the `<name>_<season>.txt` files next to `file`. A season's model is the one for that season's games, trained on the seasons before it, so a game is always predicted by a model that has never seen its season. `probability(row)` is the model's answer for one row of features (a list of numbers in the order the model was trained with; `nan` where a value is unknown): the probability of yes (a float), each class's probability (a tuple, for a model fitted with `classes`), or with `cuts` (a model from `fit_number`) the probability that the number reaches each cut (`limit` is then the place in the row of the feature the model was fitted with as its limit). With `several=True`, `probability(rows)` answers a list of rows in one call (a tuple of floats): the candidates of a choice among players, one row each. A season later than every model gets the latest model; a season earlier than every model gets `None`, and the predictor falls back. A predictor with several models gives each a `name`.
- `choose(probabilities, rng) -> int`: which candidate, drawn in proportion to such a model's answers.
- `fit(table, features, label, weight=None, rounds=150, classes=None, coarse=(), **params) -> model`: gradient-boosted trees (LightGBM) for a yes/no label, or with `classes=3` for a label that is one of three classes (0, 1, 2). `table` is a DataFrame with a column per feature and the label; `weight` is an optional weight per row; `params` override LightGBM's settings (`shared.models.training.PARAMS`).
- `fit_number(table, features, label, cuts, rounds=150, coarse=(), limit=None, **params) -> model`: the distribution of a number (yards). One yes/no model answers "does the number reach this cut?" for every cut: it is fitted to the table repeated once per cut, with the cut as one more feature, and can only answer lower as the cut rises. `limit` names a feature the number runs up against (a carry can't gain more than the yards to the goal line, and every longer gain ends on it): the model is then also told how far each cut is from it.
- `draw(reaches, cuts, rng) -> (low, high)`: a number drawn from such a model's answer, as the two cuts it falls between (`None` for no bound). Where the cuts are a yard apart that is the number; where they are wider, the predictor draws within them from a histogram (`shared.priors.hist(histogram, rng, low, high)`).
- `save_model(model, file, season, name="model") -> Path`: writes `<name>_<season>.txt` next to `file`.

`coarse` names the features a model may only read in 8 steps (each holding an equal share of the training plays): the ones that say who is playing, like a team's past rate. Read exactly, such a number is the same on every play of one team's season and different for every other team, so it picks that season out of the training plays, and the model learns what that team went on to do instead of what the rate says. Per play the score hardly shows it; a team's total over a game gets worse. Read coarsely, the same inputs help (`MAINTAINER.md`).

A training table comes from `events.training.table`, which turns every real play into a row with a predictor's own `example` function.
