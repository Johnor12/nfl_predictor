# nfl_predictor

the goal of this project is to build a system for predicting what happens during an NFL season.

definitons:
event: a discrete unit of something happening. generally has inputs (the relevant state of the world before the event) and outputs (the relevant state of the world changed by the event).
predictor: a mechanism for predicting the outcomes of an event, given its inputs. can be as simplistic as a 50/50 random number generator or as a complex as a machine learning (ML) model.
scenario: chains events together, often with domain-specific logic. encodes a real-world sequence of events, connected by logic, where the outputs of previous events are often fed into future events. stores the relevant state of the world as events operate on it. has a set of inputs describing the world before the scenario, and generates relevant outputs.
simulator: simulates many instances of an scenario, aggregating relevant outputs across those simulations.
timeline: a particular instance of a scenario

general approach: simulate many instances of the same event, then present a distribution of outcomes. an event can be composed of many events, each of which is predicted by an appropriately complex process (a game event includes a coin toss event, composed of a toss event and a decision event; the coin toss is a trivial 50/50 random generator; the model for predicting what the winning team will do with the toss is significantly more complex). the event simulator logically composes sub-event predictors, keeps track of relevant outcomes, then aggregates those outcomes across 1000's of simulations. each predictor should be as simple and concise as possible, both in its technical implementation and its scope (for example, the snap predictor should be told who is on the field (information available at the time of snap), rather than implicitly predicting that from team rosters).

complex events should generally be predicted by machine learning (ML) models trained on historical incidents of that event.

scenarios can be composed together; for example an NFL snap scenario contains a formation event and a snap event. a game scenario contains many snap scenarios. a season scenario contains many game scenarios. parent scenarios should call child scenarios directly rather than trying to recreate or handle them differently.

ML models will probably need to be trained at scale in the cloud (AWS).

in general a simulator's "simulation" step should happen at the highest level possible; a game simulator should play through a game timeline composed of concrete snap timelines, then repeat many times, rather than simulating many snap timelines at each step and attempting to average them together or something. an alternative implementation would be to "branch" from each event; run ten copies of the first snap, then apply the game scenario to each of those until we got to the second snap in each timeline, then branch again and so forth. that would result in a giant tree where the leaf nodes were completed games. the advantage would be progressively more simulations spent on deeper scenarios (which are inherently more uncertain) compared to the "flat" simulator. the disadvantage is absurd exponential growth in timelines. potentially each event could have an "uncertainty factor" which determined how much we branched from it. either way, that's an alternative approach we can consider.

the core model is a snap event predictor, which takes in the overall state of the game, including: teams playing, game location, weather, time of day, stadium turf type, coaching staff, referee team, player rosters (including injuries and depth charts), individual players' information (position, aggregate statistics for the season so far, and draft capital for rookies), field location, game score, game clock time, play clock time, team timeouts remaining, all previous snaps for the game (or a condensation of relevant information from those snaps, or just the outcomes of previous snaps), players on field for both teams, and general team formations, and predicts the outcome of the snap: the type of play, how long the play takes, players involved in the play, relevant outcomes for those players, both offensive and defensive (rushing yards, receiving yards, passes, receptions, first downs, touchdowns, kick yards, return yards, field goal makes and misses, fumbles, interceptions, sacks, tackles, and pressures), penalties (type, players involved, yardage outcome, and initiating referee if available), injuries (including how much time they cause the player to miss during the game, up to the rest of the game).

layered on top of the snap predictor is a formation event predictor, which takes all of the same inputs as the snap predictor except for the players on field and formations, and predicts players on field and formations. this model should have some hard-coded features, like guarantees that formations are legal and that players are lined up in appropriate positions.

Phase 0 is the play event simulator, which is composed of the formation event and snap event described above, predicted by ML models. The play event simulator's logic is simple; predict a formation, then feed that formation into a snap predictor.

Phase 1 is the game event simulator, which broadly takes in all information available at the start of an NFL game, then composes: coin toss event -> kick off snap (predicted by specialized instances of the formation and snap predictors) -> a sequence of play events, potentially with timeouts and coach's challenge flags between them, predicted by separate models, keeps track of all game statistics across plays and the game clock, and continues until the game concludes (including overtime if applicable). It simulates a game 1000's of times, then presents aggregated statistical distributions across those simulations.

Phase 2 is a season event simulator, which predicts all games across an NFL season and layers between-game events on top of them (practice injuries, trades, depth chart changes, free agent transactions, coaching personnel changes, and IR moves). aggregates statistics across all games. this is further out and therefore less developed.

Phase 3 is a multi-season event predictor, which chains multiple seasons together with between-season events (many of the same events from the season predictor, but including drafted players and the NFL schedule). even further out.
